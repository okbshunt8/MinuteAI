# MinuteAI

会議の音声をリアルタイムで文字起こしし、メモ・マーカー・要約までを **Mac の中だけで完結** させる macOS アプリです。
音声・文字起こし・メモ・要約は外部に送信されません。文字起こしと要約の AI モデルも Mac 上で動きます。

## できること

- **リアルタイム文字起こし**: マイクの音声と、Mac で再生中の音声(リモート会議の相手の声)を同時に録音して文字起こしします。仮想オーディオドライバは不要です。
- **文字起こしの修正**: 行をクリックすればそのまま打ち直せます。
- **マーカー**: 文字起こしの各行に4色のマーカーを付けられます。
- **章立て**: 「ここからこの話題」という見出しを文字起こしに入れられます。手で付けるほか、録音後に AI に自動で付けさせることもできます。
- **メモ**: 文字起こしの横でメモを書けます。カテゴリ(メモ・課題・タスク・決定事項・質問、追加や変更も可能)を指定でき、特定の発言に紐づけることもできます。メモをクリックすると、書いたときの発言へ移動します。
- **要約**: マーカーを付けた発言とメモを重視して、概要・主な議論・決定事項・課題・タスクの形式で要約します。
- **録音の再生と保存**: 再生位置の発言が文字起こし上で分かります。音量調整、.m4a での保存ができます。
- **会議履歴と検索**: 過去の会議を一覧し、タイトル・文字起こし・メモ・要約を全文検索できます。
- **書き出し**: Markdown / テキスト / 音声(.m4a)。
- **モデルの管理**: 文字起こし用・要約用のモデルをアプリ内でダウンロード、切り替え、削除できます。会議ごとに使うモデルを選べ、使ったモデルは会議に記録されます。

## 動作環境

| 項目 | 要件 |
|---|---|
| Mac | Apple Silicon(Intel Mac は非対応) |
| macOS | 15.0 以降 |
| メモリ | 16GB 以上を推奨(8GB の場合は軽量なモデルを選んでください) |
| ディスク | モデル用に 3〜6GB 程度の空き |
| ビルド | Xcode 26 以降(開発と動作確認は Xcode 27 / macOS 27) |

## ビルドと起動

配布用のバイナリはありません。Xcode でビルドして使います。

1. このリポジトリを取得して `MinuteAI.xcodeproj` を Xcode で開きます。
2. 初回は依存ライブラリの取得が自動で始まります(数分かかります)。
3. 実行(⌘R)します。初回ビルドは時間がかかります。

### 初回に出る確認

- **マクロの許可**: ビルド時に「Macro "MLXHuggingFaceMacros" ... must be enabled」と表示されたら **Trust & Enable** を押してください。要約ライブラリ(mlx-swift-lm)が含む Swift マクロに対する Xcode の確認です。
- **マイク**: 最初の録音開始時に許可を求められます。
- **システムオーディオ録音**: 同じく最初の録音開始時に許可を求められます。拒否するとリモート会議の相手の声が録音されません。あとから変更する場合は、システム設定 > プライバシーとセキュリティ > 画面収録とシステムオーディオ録音 で行います。

署名は開発用の簡易署名(ad-hoc)です。ビルドし直すと macOS が上記の許可を聞き直すことがあります。
Hardened Runtime は有効、App Sandbox は無効です。

### コマンドラインでビルドする場合

```sh
xcodebuild -project MinuteAI.xcodeproj -scheme MinuteAI -configuration Debug \
  -derivedDataPath .build/DerivedData -skipMacroValidation build
```

`-skipMacroValidation` は上記のマクロの確認を省略する指定です。

## 使い方

### 1. モデルを用意する

サイドバー上部の歯車ボタン(または ⌘,)で設定を開きます。

- **文字起こし** タブ: モデルをダウンロードします。「Large v3 Turbo (圧縮版)」(約630MB)が推奨です。
- **要約** タブ: この Mac のスペックと、各モデルが快適に動くかの目安(推奨 / 快適 / 重い / メモリ不足)が表示されます。「推奨」のモデルをダウンロードしてください。「Hugging Face から探す」で他のモデルを一覧から追加することもできます。

◉ を付けたモデルが既定になります。

### 2. 録音する

1. 「新しい会議」(⌘N)を押します。
2. 必要ならタイトルの下で文字起こしモデルを選びます(録音開始後は変更できません)。
3. 「録音を開始」を押します。右上のレベルメーターでマイクとシステム音声が拾えているか確認できます。
4. 話した内容が1〜2秒遅れで表示され、話の区切りで確定します。
5. 「録音を停止」で終了します。

録音する音声(マイク / システム音声)と認識する言語(日本語 / 英語 / 自動判定)は、設定の「文字起こし」タブで変更できます。
声が小さくて文字起こしされないときは、同じタブの「マイクの感度」を上げてください(録音中も変更できます)。雑音も一緒に大きくなるので、上げすぎには注意してください。

### 3. 文字起こしを直す・印を付ける

- 行をクリックするとカーソルが入り、そのまま修正できます。内容はその場で保存されます。
- 行にカーソルを乗せると出るボタンで、マーカーを付けたり、その発言へのメモを書き始めたりできます。
- 行の余白を右クリックすると、マーカー・メモへの追加・行の削除などのメニューが出ます。

### 章立て(見出し)を付ける

- **手で付ける**: 行にカーソルを乗せると出るボタン、または右クリック →「ここから新しい章」で、その行の上に見出しを追加します。録音中でも付けられます。見出しはクリックして書き換えられ、空にすると消えます。
- **AI に付けさせる**: 録音後、文字起こしの上部にある「章立てを生成」を押すと、話題の区切りに見出しが付きます。その会議の要約用モデルを使います。手で付けた見出しは変更されず、AI が付けた見出しだけが作り直されます。
- 見出しがあると、上部の「章」メニューからその位置へ移動できます。見出しは要約と書き出しにも反映されます。

### 4. メモを書く

- 右側の「メモ」タブで、カテゴリを選んで入力します。Enter で追加、⌥Enter で改行です。
- ⌘1〜⌘9 でカテゴリを切り替えられます。
- メモは会議の時間順に並びます。
- メモ・文字起こし・再生位置は連動しています。メモを選ぶと該当する発言と再生位置へ移動し、発言を選ぶ(または再生位置が進む)と、その発言のメモが枠で示されます。
- 紐づける発言をあとから変えるには、メモにカーソルを乗せると出るリンクのボタンを押してから、文字起こしの正しい行をクリックします。
- 「タスク」カテゴリのメモには完了チェックが付きます。
- 編集はカーソルを乗せると出る鉛筆ボタン、または右クリックから行います。削除には確認が出ます。
- **画像を貼る**: メモ欄を表示した状態で ⌘V を押すと、クリップボードの画像(スクリーンショットなど)が入力中のメモに付きます。入力欄の左の画像ボタンからファイルを選ぶか、画像ファイルをメモ欄にドラッグしても貼れます。貼った画像はクリックで拡大できます。

### 5. 要約する

右側の「要約」タブで「要約を生成」を押します。ボタンの隣のメニューで、その会議に使うモデルを選べます。
要約は押した時点の文字起こしとメモから作られるので、文字起こしを修正したあとは「再生成」してください。要約は手で編集することもできます。
再生成しても、新しい要約が最後まで書き上がるまで元の要約は残ります(中止や失敗の場合は元のままです)。

### 6. 再生する・書き出す

- 録音後は画面下部に再生バーが出ます(⌥Space で再生 / 一時停止)。
- 文字起こしの時刻をクリックするとそこから再生します。行を選ぶと再生位置がその発言に移ります。
- スピーカーのスライダーで再生音量を調整できます(100% が録音そのまま)。
- 「音声を保存」で .m4a を保存できます。右上の書き出しメニューから Markdown / テキストも保存できます。

## データの保存場所とプライバシー

すべて次のフォルダに保存されます。

```
~/Library/Application Support/MinuteAI/
├── Meetings/<会議ID>/meeting.json   文字起こし・メモ・要約
├── Meetings/<会議ID>/audio.m4a      録音
├── Meetings/<会議ID>/images/        メモに貼った画像
└── Models/                          ダウンロードしたモデル
```

アプリがインターネットに接続するのは次の場合だけです。いずれも接続先は Hugging Face で、会議の内容は送信しません。

- モデルをダウンロードするとき
- 設定の「Hugging Face から探す」でモデルの一覧を取得するとき

アプリを削除してもこのフォルダは残ります。データを消すにはフォルダごと削除してください。

## 注意事項

- **長時間の会議は十分に検証できていません。** 開発時に確認できたのは数分程度の録音です。長い会議で使う前に、10〜20分ほどの録音で試すことを勧めます。
- **録音中に問題が起きた場合**(音声の保存に失敗した、デバイスの切り替え後に録音を再開できなかった、文字起こしに失敗した区間がある など)は、会議タイトルの下にオレンジ色の警告が出ます。
- **録音中に終了しようとすると確認が出ます。**「停止して終了」を選ぶと、残りの音声を文字起こししてから終了します(最長60秒)。録音中にウィンドウを閉じても録音は続きます。
- **録音中は蓋を閉じないでください。** 録音中は自動スリープを抑止していますが、蓋を閉じた場合や手動でスリープさせた場合は録音が止まります。
- **一度停止した会議に録音を追加することはできません。** 続きは新しい会議として録音してください。
- **録音が中断された場合の復旧**: 録音中にアプリが落ちても、次回起動時に音声を自動で復旧します。そのための控えとして、録音中だけ1時間あたり約350MBのディスクを一時的に使います。
- **長い会議の要約**: 文字起こしが約1.4万字(45分前後)を超えると、分割して要点を抜き出してからまとめます。全文を読む場合より細部が落ちやすいので、重要な発言にはマーカーやメモを付けてください。極端に長い会議(10時間級)は、メモリ不足で要約に失敗する可能性があります。
- **音声認識と要約には誤りが含まれます。** 固有名詞や専門用語は誤認識されやすく、要約にもそのまま反映されます。重要な内容は必ず確認してください。
- **メモの画像は要約には使われません。** 要約モデルが読むのは文字起こしとメモの文章だけです。Markdown の書き出しでは、画像は .md ファイルと同じ場所の「<ファイル名>-images」フォルダにコピーされます。他の人に渡すときはこのフォルダも一緒に渡してください。
- **話者の区別はありません。** マイクとシステム音声は1つにミックスして文字起こしします。
- **再生音量を上げすぎると音が割れます。** 保存される音声ファイルの音量は変わりません。
- **スピーカーで会議音声を流している場合**、マイクも同じ音を拾うため音が二重に録音されます。イヤホンやヘッドホンの利用を勧めます。
- **録音の同意**: 会議を録音・文字起こしする際は、参加者の同意や所属組織のルールを確認してください。
- **モデルのライセンス**: ダウンロードするモデルにはそれぞれ利用条件があります(Gemma は Google の利用規約など)。Hugging Face の各モデルのページで確認してください。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| Xcode から実行すると要約の生成中に停止する(`MTLDebugComputeCommandEncoder ... failed assertion`) | Product → Scheme → Edit Scheme… → Run → Diagnostics で「Metal API Validation」をオフにします。リポジトリ同梱のスキームではオフになっています。 |
| 相手の声が文字起こしされない | 「システムオーディオ録音」の許可と、設定の「システム音声」がオンになっているかを確認します。録音中に右上のスピーカー側のレベルメーターが動けば拾えています。 |
| 最初の録音開始に時間がかかる | モデルを初めて読み込むときは最適化のため1分以上かかることがあります。2回目以降は数秒です。 |
| 再生しても音が聞こえない | 再生バーの時刻が進んでいれば音量の問題です。音量スライダーを上げてください。 |

## 開発者向け

### 構成

```
MinuteAI/
├── Models/      会議・発言・メモのデータ構造
├── Services/    録音、文字起こし、要約、モデル管理、保存
└── Views/       画面
Config/Info.plist  マイク / システム音声の利用目的
```

主な依存ライブラリ:

- [WhisperKit](https://github.com/argmaxinc/WhisperKit) — 文字起こし(Whisper を Core ML で実行)
- [mlx-swift-lm](https://github.com/ml-explore/mlx-swift-lm) — 要約(言語モデルを MLX で実行)
- [swift-transformers](https://github.com/huggingface/swift-transformers) — トークナイザ

### セルフテスト

デバッグビルドには、マイクや画面操作なしで文字起こしと要約を確認する仕組みがあります。音声ファイルを録音時と同じ処理に流し、結果を標準出力に表示します。

```sh
# 文字起こしのみ
MINUTEAI_SELFTEST=/path/to/audio.wav \
  .build/DerivedData/Build/Products/Debug/MinuteAI.app/Contents/MacOS/MinuteAI

# 要約まで実行
MINUTEAI_SELFTEST=/path/to/audio.wav MINUTEAI_SELFTEST_SUMMARY=1 \
  .build/DerivedData/Build/Products/Debug/MinuteAI.app/Contents/MacOS/MinuteAI

# 保存済みの会議 (meeting.json) に対して章立ての生成だけを実行
MINUTEAI_SELFTEST_CHAPTERS=/path/to/meeting.json \
  .build/DerivedData/Build/Products/Debug/MinuteAI.app/Contents/MacOS/MinuteAI
```

設定で選択中のモデルを使い、未ダウンロードの場合はダウンロードします。
